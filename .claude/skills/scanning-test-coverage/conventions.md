# Test Conventions

Project standards for unit tests discovered and generated by this skill.

| Aspect | Standard |
|--------|----------|
| Framework | xUnit (`[Fact]`, no `[Theory]`) |
| Test file per | One per source class (1:1), or per feature area when grouped |
| Test file pattern | `{ClassName}Tests.cs` (grouped files may use a feature name instead) |
| Project pattern | `{SourceProject}.Tests` (e.g., `ECS.Tests`, `Engine.Tests`) |
| Namespace | `{SourceNamespace}.Tests` (e.g., `Engine.Tests.Components`) |
| Method naming | `{Method}_{Scenario}_{Expected}` |
| Assertions | Shouldly (`Should`, `ShouldBe`, `ShouldNotBeNull`, etc.) in all test projects |
| Mocking | NSubstitute (sparingly used) |
| Fake data | Bogus `Faker` |
| Test class structure | Public class, optional `IDisposable`, private inner test-double classes |

## Assertions

Use Shouldly in every test project (`tests/ECS.Tests/`, `tests/Engine.Tests/`, etc.). Do not use xUnit `Assert`.

## Stub template

```csharp
namespace Engine.Tests.Components;

public class MyComponentTests
{
    // TODO: Implement tests
    // Test method pattern: {Method}_{Scenario}_{Expected}
    // Use [Fact] (no [Theory])
    // Use Shouldly for assertions (Should, ShouldBe, ShouldNotBeNull, etc.)
    // Use Bogus Faker for randomized test data
    // Use NSubstitute for mocking dependencies
}
```

**Verify stubs compile**: `dotnet build` in the test project directory.
